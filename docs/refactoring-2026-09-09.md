# Завершение рефакторинга — 9 сентября 2026

## Денежные расчёты

Денежные поля и курсы переведены на Decimal в приложении и NUMERIC в PostgreSQL.
Общий тип `app/money.py` нормализует присваивания моделям и проверяет конечность
значений. Обновлены проведение операций, остатки, кредиты, цели, бюджеты,
семейная аналитика, отчёты, повторяющиеся операции и импорт.
JSON курсов провайдеров разбирается сразу в Decimal.

HTTP-контракт сохранён: ответы по-прежнему содержат JSON-числа. Поэтому точность
чисел на стороне JavaScript ограничена Number; гарантия Decimal относится к
расчётам backend и хранению PostgreSQL. Для входных значений, переданных строкой,
нет промежуточного float; ключ идемпотентности различает суммы за пределами
точности float. SQLite остаётся облегчённым тестовым окружением с Float-хранением.

Миграция `a0193a000002` преобразует все денежные колонки, сверяя каждое значение
с десятичным текстовым представлением прежнего Float. Исходную погрешность Float
она не восстанавливает. NaN/Infinity отклоняются; downgrade отклоняется, если
он потеряет новую точность. Все изменения миграции транзакционны.

## Границы ответственности

Политика исторических снимков выделена в `services/exchange_snapshots.py`.
Прежние импорты через `services/exchange.py` сохранены. Перед построением
отчёта `report_db` автоматически закрепляет недостающие снимки пользователя
пакетами по 500 записей. Сохранённые курсы не переоцениваются. Недостающая
сторона перевода использует уже сохранённую валюту оценки.

Курсы провайдеров сохраняются в `exchange_rates` с TTL 24 часа. Перезапуск
приложения не теряет этот кеш; при недоступности провайдера можно использовать
прежний сохранённый курс. В памяти остаётся только ускоряющий кеш расчётов
в пределах транзакции; откат не переносит его значения в следующий запрос.

Первое открытие старого отчёта может сохранять недостающие снимки и курсы.
Повторный расчёт по подготовленным данным не изменяет исторические снимки.
Сохранением управляет явная зависимость `financial_db` перед успешным HTTP-ответом;
универсальный `get_db` сам не коммитит. Оценка старой записи без снимка закрепляется
по первому доступному курсу, а не по восстановленному историческому курсу ЦБ.
Если курс недоступен, следующая подготовка повторяет попытку.

Для необязательной предварительной пакетной подготовки из `backend`:

```powershell
python scripts/repair_exchange_snapshots.py
python scripts/repair_exchange_snapshots.py --user-id 123
```

На рабочей и production-базах команда вручную не запускалась.
Текущие результаты проверки этой схемы — в `refactoring-2026-09-10.md`.

Загрузка данных главной страницы выделена в `useHomeData`, включая кеш,
поэтапную загрузку и защиту от устаревших ответов. Сортировка и перенос счетов
выделены в `useAccountOrdering`. Контроллеры страниц собирают эти части.

## Выпуск

Изменения подготовлены в рабочей копии; production-деплой не выполнялся.
Для выпуска требуется резервная копия и применение Alembic `upgrade head`
в согласованном обновлении backend. Изменение Float → NUMERIC блокирует
изменяемые таблицы на время миграции. После появления точных значений откат
к Float может быть намеренно запрещён проверкой миграции.
