# Полный перенос CaseMoney на Amvera

CaseMoney разворачивается как два ресурса Amvera:

1. managed PostgreSQL `casemoney-db`;
2. одно Docker-приложение `casemoney`, в котором FastAPI обслуживает API и собранный React/PWA.

До окончательной проверки не удаляйте Render и Neon: они остаются быстрым вариантом отката.

## 1. Создание PostgreSQL

1. В Amvera Cloud нажмите **Создать → PostgreSQL**.
2. Название проекта: `casemoney-db`.
3. Если доступен выбор версии, укажите PostgreSQL 18 — текущая Neon работает на PostgreSQL 18.
4. Для первого запуска достаточно одной реплики и тарифа не ниже рекомендованного Amvera **Начальный**.
5. Задайте отдельные имя базы, пользователя и длинный пароль. Не используйте зарезервированные имена `postgres`.
6. Дождитесь статуса **PostgreSQL запущен**.
7. На вкладке **Инфо** сохраните внутренний адрес чтения/записи, оканчивающийся на `-rw`.
8. В настройках базы временно создайте внешний домен с типом подключения **POSTGRES**. Он нужен только для переноса с локального компьютера.

Не публикуйте пароли и строки подключения в GitHub, сообщениях или снимках экрана.

## 2. Пробный перенос базы

Если локальная сеть не пропускает соединения к Neon на порту 5432, используйте ручной workflow GitHub Actions **Migrate database to Amvera**. В настройках репозитория создайте secrets `NEON_DATABASE_URL` и `AMVERA_DATABASE_URL`, затем запустите workflow с подтверждением `MIGRATE`. Dump существует только во временном каталоге runner и удаляется в конце; в артефакты он не загружается.

На компьютере уже установлены `pg_dump`, `pg_restore` и `psql` версии 18.4. Откройте PowerShell в корне проекта и задайте две переменные только в текущем окне:

```powershell
./migrate_database.ps1 `
  -AllowOlderTarget `
  -TargetHost casemoney-db-solo32.db-msk0.amvera.tech `
  -TargetUser casemoneyuser `
  -TargetDatabase casemoney
```

Сценарий скрыто запросит полную строку Neon и пароль Amvera. Они не выводятся на экран и не сохраняются в файлах. Параметр `-AllowOlderTarget` разрешает наш проверяемый логический перенос PostgreSQL 18 → 17.5; исходная Neon при этом не изменяется, а восстановление выполняется одной транзакцией.

Сценарий:

- проверяет соединения и совместимость версий PostgreSQL;
- отказывается работать, если целевая база не пуста;
- создаёт локальный dump, не меняя Neon;
- восстанавливает данные в Amvera одной транзакцией;
- сравнивает список таблиц и точное количество строк;
- сохраняет локальный JSON-отчёт проверки.

Dump и отчёт находятся в `migration-artifacts/` и исключены из Git. Они содержат конфиденциальные данные.

Если приложение уже успело создать таблицы в новой базе, его нужно остановить и повторить перенос только для этой новой базы:

```powershell
./migrate_database.ps1 `
  -ResetTarget `
  -AllowOlderTarget `
  -TargetHost casemoney-db-solo32.db-msk0.amvera.tech `
  -TargetUser casemoneyuser `
  -TargetDatabase casemoney
```

Параметр `-ResetTarget` удаляет схему `public` целевой базы. Никогда не применяйте его к рабочей базе.

## 3. Создание приложения

1. Создайте в Amvera ресурс типа **Приложение** с именем `casemoney`.
2. Во вкладке **Репозиторий** подключите GitHub, ветку `main`, событие `Push` и webhook согласно подсказкам Amvera.
3. После загрузки кода Amvera использует корневые `amvera.yml` и `Dockerfile`.

### Секреты приложения

| Название | Значение |
| --- | --- |
| `DATABASE_URL` | Внутренняя строка Amvera: `postgresql://<user>:<url-encoded-password>@amvera-<account>-cnpg-casemoney-db-rw:5432/<database>?sslmode=disable` |
| `SECRET_KEY` | Тот же production-ключ, который используется на Render, чтобы не сбросить активные JWT-сессии |
| `POSTBOX_ACCESS_KEY_ID` | ID статического ключа сервисного аккаунта Yandex Cloud |
| `POSTBOX_SECRET_ACCESS_KEY` | Секрет статического ключа сервисного аккаунта |

Пароль внутри URL необходимо URL-кодировать, если в нём есть `@`, `:`, `/`, `?`, `#` или `%`.

### Обычные переменные

| Название | Значение |
| --- | --- |
| `APP_URL` | Сначала бесплатный HTTPS-домен Amvera, после переключения — `https://casemoney.ru` |
| `CORS_ORIGINS` | `https://casemoney.ru,https://www.casemoney.ru` |
| `POSTBOX_FROM_EMAIL` | `no-reply@casemoney.ru` |
| `POSTBOX_FROM_NAME` | `CaseMoney` |
| `POSTBOX_ENDPOINT_URL` | `https://postbox.cloud.yandex.net` |
| `REGISTRATION_NOTIFY_EMAIL` | `andrey.zakhartsev@gmail.com` |
| `RATELIMIT_ENABLED` | `1` |
| `WEB_CONCURRENCY` | `1` |

`VITE_API_URL` задавать не нужно: frontend обращается к API на том же домене.

При запуске контейнер автоматически выполняет `alembic upgrade head`, а затем запускает FastAPI. Схема по-прежнему меняется только миграциями Alembic; `create_all` не используется.

## 4. Проверка на временном домене

Добавьте приложению бесплатный HTTPS-домен Amvera и проверьте:

- `/health` возвращает `{"status":"ok"}`;
- `/health/ready` возвращает `{"status":"ready"}`;
- вход существующим пользователем;
- счета, операции и отчёты совпадают с production;
- небольшая тестовая операция создаётся и удаляется;
- регистрационное письмо отправляется;
- `/about` показывает актуальную версию PWA.

После теста удалите тестовую операцию. Пока основной домен ведёт на Render, не используйте одновременно обе версии для реальной работы: после пробного копирования базы начинают расходиться.

## 5. Финальная синхронизация без потери записей

Выполняйте в период минимальной активности:

1. Остановите приложение Amvera.
2. Временно приостановите backend Render, чтобы новые записи больше не попадали в Neon.
3. Повторно задайте переменные подключения в PowerShell и выполните:

   ```powershell
   ./migrate_database.ps1 `
     -ResetTarget `
     -AllowOlderTarget `
     -TargetHost casemoney-db-solo32.db-msk0.amvera.tech `
     -TargetUser casemoneyuser `
     -TargetDatabase casemoney
   ```

4. Убедитесь, что сценарий сообщил о совпадении всех таблиц.
5. Запустите приложение Amvera и проверьте `/health/ready` на временном домене.
6. Создайте ручной backup базы в интерфейсе Amvera и включите ежедневные backup по расписанию.
7. Только после этого переключайте DNS `casemoney.ru`.

Если проверка не прошла, не переключайте DNS: снова запустите Render, Neon при переносе не изменяется.

## 6. Переключение casemoney.ru

1. По возможности заранее уменьшите TTL записей `@` и `www` до 300 секунд.
2. Добавьте в Amvera домены `casemoney.ru` и `www.casemoney.ru` с типом HTTPS.
3. В REG.RU замените старые web-записи только на A/TXT, которые покажет Amvera.
4. Не удаляйте DKIM `*_domainkey` и остальные почтовые записи Yandex Postbox.
5. Дождитесь подтверждения домена и выпуска SSL-сертификата.
6. Проверьте сайт без VPN через домашний и мобильный интернет.
7. Установите `APP_URL=https://casemoney.ru` и перезапустите приложение.

Render и Neon оставьте доступными минимум на 72 часа. Neon не используйте для новых записей; это только аварийная копия состояния до переключения.

## 7. После переезда

- удалите внешний POSTGRES-домен базы Amvera: приложению достаточно внутреннего `-rw` адреса;
- очистите из текущего PowerShell строки подключения:

  ```powershell
  Remove-Item Env:CASEMONEY_SOURCE_DATABASE_URL
  Remove-Item Env:CASEMONEY_TARGET_DATABASE_URL
  ```

- перенесите локальный dump в защищённое хранилище или безопасно удалите его;
- проверьте ежедневные backup Amvera;
- через 72 часа отключите старые сервисы Render, но удаляйте Neon только после отдельного подтверждения, что backup Amvera восстанавливается.
