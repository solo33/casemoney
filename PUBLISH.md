# CaseMoney — подготовка к публикации

Документ закрывает 4 вопроса: юридические требования, тестовый хостинг,
тест-кейсы и автоматизацию, и «что могли забыть».

---

## 1. Юридические требования — что должно быть на сайте

Приложение хранит email и финансовые данные физлиц → попадает под РФ 152-ФЗ
«О персональных данных». Минимально необходимое:

### Обязательно (публичные страницы со ссылками в подвале / на логине)
1. **Политика конфиденциальности (обработки персональных данных)** —
   что собираем (email, имя, операции/суммы), зачем, где храним, срок,
   передача третьим лицам (нет), права пользователя, контакт оператора.
   Требование 152-ФЗ ст. 18.1.
2. **Согласие на обработку ПДн** — чекбокс при регистрации со ссылкой на
   политику («Регистрируясь, я соглашаюсь…»). Без проставленного согласия
   регистрацию не завершать.
3. **Пользовательское соглашение (Terms of Use)** — правила использования,
   отказ от ответственности (сервис «как есть», не финансовый консультант),
   условия Free/Premium.
4. **Контакты / реквизиты оператора** — кто владелец сервиса (ФИО ИП /
   самозанятый / юрлицо), email для обращений. Для сторов это тоже нужно.

### Если будут платежи за Premium (сейчас активация тестовая, без оплаты)
5. **Публичная оферта** + условия возврата.
6. Чеки самозанятого/ИП через «Мой налог»/кассу, привязка к платёжному
   провайдеру (ЮKassa/CloudPayments).

### Технические требования РФ
7. **Уведомление в Роскомнадзор** об обработке ПДн (оператор ПДн) —
   подаётся до начала обработки; для самозанятых/ИП тоже.
8. **Хранение ПДн граждан РФ на серверах в РФ** (152-ФЗ ст. 18 ч.5) →
   при выборе хостинга брать **российский** (см. п.2).
9. Cookie-уведомление, если используются аналитика/трекинг (сейчас нет).

### Для сторов (RuStore / AppGallery)
10. Privacy Policy URL — обязательное поле карточки.
11. Заполнение «Сбор данных»: email, финансовые данные, шифрование в
    транзите (HTTPS), удаление по запросу (у нас уже есть «Удалить аккаунт»).

> Что уже есть в коде в пользу соответствия: удаление аккаунта и всех данных
> (Настройки → Опасная зона), экспорт своих данных в CSV (право на доступ),
> хранение паролей через bcrypt, JWT, отсутствие доступа админа к чужим
> операциям. Не хватает: публичных страниц (1,3), чекбокса согласия (2),
> реквизитов (4), уведомления РКН (7).

**Следующий шаг по #1:** сгенерировать страницы `/privacy`, `/terms`,
`/contacts` (RU-текст) + чекбокс согласия на регистрации + ссылки в подвале
логина. Готов сделать отдельным заходом — текст шаблонный, подставить
реквизиты оператора.

## 2. Тестовая публикация — бесплатный вариант

Нужно: публичный HTTPS-домен, бэкенд (FastAPI), Postgres, статика фронта.

### Рекомендация (бесплатно, но не в РФ — для теста ОК; для прод-ПДн нужен РФ-хостинг)
**Вариант A — всё на одном бесплатном PaaS:**
- **Render.com** (free tier): Web Service (FastAPI, Docker/Python) +
  Postgres (free 90 дней / далее платно) + бесплатный HTTPS-сабдомен
  `*.onrender.com`. Фронт — Static Site там же. Минус: free-инстанс
  «засыпает» (холодный старт ~30 сек) — для теста терпимо.
- **Fly.io** — 3 микро-ВМ бесплатно + Postgres; быстрее, чуть сложнее.
- **Frontend отдельно: Netlify / Vercel / Cloudflare Pages** (бесплатно,
  быстрый CDN) — собирает `frontend/dist`, env `VITE_API_URL` на бэкенд.

**Вариант B (российский, под 152-ФЗ для боевого запуска):**
- **Timeweb Cloud / Selectel / Yandex Cloud** — есть стартовые гранты,
  не полностью бесплатно, но данные в РФ. Для реального запуска с ПДн
  граждан РФ — это правильный путь.

### Минимальный план для теста (бесплатно)
1. Фронт → **Cloudflare Pages** (бесплатно, HTTPS, свой сабдомен).
2. Бэк + Postgres → **Render** free.
3. Прописать `VITE_API_URL` фронта на адрес бэка; `APP_URL` бэка на адрес фронта.
4. Секреты на хостинге (НЕ в git): `SECRET_KEY`, `DATABASE_URL`, SMTP.
5. Прогнать `alembic upgrade head` на удалённой БД.

**Что нужно подготовить в репо для деплоя (сейчас отсутствует):**
- `backend/Dockerfile` (или `render.yaml` / `Procfile`) и
  `requirements.txt` зафиксировать.
- `backend/.env.example` (без значений) — список нужных переменных.
- CORS на бэке под прод-домен фронта (проверить middleware).
- Прод-режим: `uvicorn` без `--reload`, воркеры, healthcheck `/`.

> Готов сгенерировать Dockerfile + render.yaml + .env.example следующим шагом.

## 3. Тест-кейсы и автоматизация

### Критичные тест-кейсы (ручной прогон перед публикацией)

**Аутентификация**
- TC-01 Регистрация нового email → письмо/активация (если включена).
- TC-02 Повторная регистрация того же email → ошибка.
- TC-03 Вход с верным/неверным паролем.
- TC-04 Доступ к защищённым страницам без токена → редирект на логин.
- TC-05 Смена пароля; вход со старым паролем больше не работает.
- TC-06 Сброс/протухание токена.

**Счета и группы**
- TC-10 Создание счёта, группы; перенос счёта между группами (drag).
- TC-11 Сортировка счетов внутри группы — порядок сохраняется после F5.
- TC-12 Мультивалютный счёт: добавить валюту, изменить, удалить (ненулевой → запрет).
- TC-13 «Учитывать в балансе» off → счёт исключён из total/группы/валют.

**Операции**
- TC-20 Добавить расход/доход/перевод; баланс счёта меняется корректно
  (перевод — нейтрален).
- TC-21 Быстрое добавление (мобильный FAB) + встроенная форма (десктоп).
- TC-22 Редактирование: смена суммы/категории/счёта/типа → балансы пересчитаны.
- TC-23 Удаление операции → баланс откатывается.
- TC-24 Дата формы синхронна с лентой «за день».
- TC-25 Фильтры в Записях (тип, счёт, категория, даты, поиск, пагинация).

**Мультивалютность / курсы**
- TC-30 Смена основной валюты → все итоги пересчитаны.
- TC-31 Ручной курс валюты применяется в отчётах/балансе.

**Анализ / отчёты**
- TC-40 Период День/Месяц/Год + стрелки + «Сегодня».
- TC-41 Пирог: проценты корректны (нет >100%), легенда, drill-down.
- TC-42 Денежный поток за год; Годовые балансы (остатки на конец месяца).
- TC-43 Клик по сумме категории → Записи с фильтром.

**Импорт / экспорт / история**
- TC-50 Импорт HomeMoney CSV: превью, корректные суммы/категории/счета.
- TC-51 Экспорт CSV скачивается и совместим с импортом (round-trip).
- TC-52 История: created/edited/deleted появляются; удалённое читаемо.

**Тарифы / лимиты / админка**
- TC-60 Free-лимиты (счета/категории/валюты) → HTTP 402 при превышении.
- TC-61 Premium снимает лимиты; срок истёк → снова лимиты.
- TC-62 Стартовый тариф из админки применяется к новой регистрации.
- TC-63 Админ не имеет доступа к чужим операциям.

**Безопасность / прочее**
- TC-70 Чужой ресурс по id (счёт/операция) → 404/403 (изоляция по user_id).
- TC-71 Удаление аккаунта стирает все данные.
- TC-72 PWA: офлайн-загрузка, установка, иконки.

### Можно ли автоматизировать? — Да, и нужно

- **Backend (приоритет): pytest + httpx/TestClient.** Поднять тестовую БД
  (SQLite или ephemeral Postgres), фикстуры пользователя/токена, и покрыть
  TC-01..06, 10..13, 20..23, 30..31, 60..63, 70..71. Это самый быстрый ROI:
  бизнес-логика балансов/лимитов/изоляции проверяется без UI. Реально за
  1-2 дня сделать каркас + 30-40 тестов.
- **E2E (вторым этапом): Playwright.** Сценарии регистрация→добавить
  операцию→увидеть в ленте→отчёт. Хорошо ловит регрессии UI, но дороже в
  поддержке. 8-12 ключевых сценариев достаточно.
- **CI: GitHub Actions** — на каждый push гонять `pytest` + `npm run build`
  (+ опц. Playwright). У тебя уже есть токен `gh`; workflow добавить просто.
- Что автоматизировать НЕ стоит: визуальную вёрстку отчётов, точность
  курсов ЦБ/CoinGecko (внешние API — мокать).

> Сейчас в проекте тестов нет. Рекомендую начать с pytest на backend
> (балансы, лимиты, изоляция) — это и есть «фундамент» перед публикацией.

## 4. Что могло быть забыто / что ещё нужно

### Перед публикацией — важное
- **CORS** под прод-домен (иначе фронт не достучится до API).
- **Rate limiting** на /auth (логин/регистрация) — защита от перебора.
- **Сброс пароля по email** («Забыли пароль?») — сейчас сбросить может
  только админ. Для публичного сервиса это обязательно.
- **Бэкапы БД** (автоснапшоты у хостера).
- **Логи и мониторинг ошибок** (Sentry free tier).
- **Healthcheck-эндпоинт** и корректный прод-запуск (без --reload).
- **Лимит размера загружаемого CSV** при импорте (защита).
- **Подтверждение email реально работает** на проде (SMTP, а не консоль).

### UX / фичи, которых не хватает
- **Восстановление пароля** (см. выше) — критично.
- **Настоящие переводы между счетами** (сейчас перевод не двигает балансы —
  это «пометка»). Полноценный перевод: списать с А, зачислить на Б, в т.ч.
  с конвертацией валют.
- **Повторяющиеся операции** (подписки, зарплата, аренда) — авто-создание.
- **Бюджеты/лимиты по категориям** (в HomeMoney есть «Бюджет»).
- **Поиск/фильтр в Истории**, фильтр по типу действия.
- **Тёмная тема** (опционально).
- **Онбординг** для нового пользователя (пустые состояния → подсказки).
- **Локализация чисел/дат** уже ок; англоязычная версия — на будущее.

### Контент для сторов
- Скриншоты (телефон 1080×1920, мин. 3), иконка 512/216, фичеграфика.
- Описание (краткое ≤80, полное), категория «Финансы», возрастной рейтинг.
- Privacy policy URL (см. #1), демо-аккаунт для модерации.
